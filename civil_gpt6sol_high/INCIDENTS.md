# 실행 중단·복구 기록

점수나 정오를 확인하지 않은 상태에서 아래 기술적 문제를 처리했다. 모든 원본 로그는 회차별 `runs/`에 남아 있다.

## 1. CLI 시작 안내를 도구 호출로 잘못 분류

첫 OFF 1회차의 앞 5묶음은 모델 호출을 정상 종료했지만, Codex의 실험적 기능 안내가 `item.type=error`로 기록되어 도구 감사에서 거절됐다. 이 안내는 모델 턴 시작 전의 고정된 CLI 메시지였다.

사전등록 보정 1에서 해당 안내만 허용하도록 검사를 수정했다. 모델·질문·프롬프트·허용 도구는 변경하지 않았다. 5묶음 모두 원응답의 바이트를 그대로 보존하여 봉인했고, 새 풀이 호출은 하지 않았다. 증거는 `meta/startup_notice_recovery.json`이다.

## 2. 연결 단절로 ON 1회차의 5묶음 미완료

처음 실행한 ON 1회차 앞 5묶음에서 스트림 연결 단절과 재접속 대기가 반복됐다. 교재 검색 터널도 끊긴 것을 확인했다. 다섯 묶음 모두 최종 완료 턴과 응답 파일이 없었으며, 해당 프로세스만 종료하고 미완료 시도를 보존했다. 단순 종료 코드가 0이더라도 완료 턴이 없는 결과를 채택하지 않았다.

기본 통신의 중립 연결 점검도 응답 시간 초과로 끝났다. 같은 공식 Codex 엔드포인트·동일 계정·GPT-6 Sol/high로 수행한 SSE 통신 점검은 정상 응답했다. 사전등록 보정 2에 따라 후속 호출은 SSE를 사용한다. 모델·문제·풀이 지침·자료 범위·출력 형식은 유지했다.

교재 서버의 원래 프로세스가 살아 있는 것을 확인하고 SSH 연결만 복구했다. 18개 문서·17,167개 임베딩, 교재 DB SHA-256이 사전등록 값과 같고 중립 검색이 작동함을 검증했다. 기록은 `civil_setup/RESTORED.json`에 있다.

ON 1회차의 미완료 다섯 묶음은 `attempt_01`로 보존하고 동일 풀이 조건의 `attempt_02`로 재실행했다. 원래 OFF 1회차의 70문항은 다시 풀지 않았다. 정답표는 이 복구 과정에서 내려받거나 열람하지 않았다.

기본 WebSocket 전송과 후속 SSE 전송의 차이, 장시간 중단은 실행 환경의 차이로 공개한다. 경과 시간을 정상적인 연속 응시 시간으로 해석할 수 없다.

## 3. ON 3회차의 사용량 한도

ON 3회차 앞 5묶음 중 3묶음(21문항)은 봉인됐고, 1–7번과 15–21번 묶음은 사용량 한도로 최종 응답 없이 실패했다. 사용자 재개 요청 후 현재 계정의 사용 허용 상태를 다시 확인했으며 사용 가능한 것으로 반환됐다. 초기화 크레딧을 소모하거나 구매하지 않고, 완료된 묶음은 건너뛰고 실패한 두 묶음만 동일 조건으로 재실행했다. 이후 후반 35문항을 진행한다. 실패한 원본 로그는 해당 회차의 `attempt_01`에 보존했다.
