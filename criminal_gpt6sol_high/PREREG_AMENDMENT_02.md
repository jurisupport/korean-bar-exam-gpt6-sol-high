# 사전등록 수정 02 — 원본의 조건별 3회 범위로 복원

사용자가 “총 3회 응시해야 하는거 아님?”이라고 지적했다. 원본 프로토콜은 도구 미사용 3회와 도구 사용 3회, 총 6개 1차 회차다. 조정자가 최초 요청을 각 1회로 축소한 것은 범위 판단 오류였다. 이를 바로잡아 기존 각 1회를 보존하고 각 조건 2회씩 추가한다.

## 실행 전에 고정한 추가 범위

- 모든 평가 모델은 기존과 동일한 gpt-6-sol, reasoning effort high다.
- 추가 1차 순서: off_p2 → on_p2 → off_p3 → on_p3. 매 회차는 원본과 동일한 8문항씩 5개 독립 배치다.
- 추가 4개 1차 회차 완료 후 ON 2·3회차에서 신뢰도 0.70 미만으로 선택된 문항만 각각 새 세션으로 재검토한다. 1차 답이나 정답은 제공하지 않으며 1차 점수를 대체하지 않는다.
- 완료된 off_p1, on_p1, on-repass_p1의 답안·로그·SEAL은 변경하지 않는다. 재개 시 기존 봉인 시각도 보존한다.
- 기존 프롬프트·문제·스키마·검색 래퍼·MCP 설정은 바이트 단위로 유지한다. CONTINUATION.json에 이들 해시와 기존 3개 SEAL 해시를 고정한다.
- 추가 실행도 새 임시 폴더, 새 ephemeral 대화로 진행한다. 조정자 대화·기존 점수·오답 번호·기존 답안·정답표는 입력하지 않는다. OFF는 도구 없음, ON은 기존 세 가지 검색 경로만 허용하고 도구 호출을 감사한다.
- 추가 회차를 점수나 정오에 따라 더 늘리거나 선택하지 않는다. 기술적 실패만 기록 후 동일 조건으로 복구한다.

## 먼저 채점한 사실과 해석상 한계

- 최초 정답표 공개·채점은 2026-09-24T15:01:31.867672+00:00에 이미 이뤄졌다. 당시에는 조건별 1회와 그 진단 회차만 완료돼 있었다.
- 따라서 전체 6회가 최초 정답 공개 전에 사전등록·완료됐다고 주장하지 않는다. 추가 4회는 사용자 범위 정정에 따른 후속 반복 실험이다.
- 기존 KEY_REVEAL.json은 수정하지 않는다. 최초 1회 비교의 보고서·요약·검증·조건 해시는 meta/round1_snapshot에 보존한다.
- 기존 키를 숨기거나 삭제해서 미열람 상태로 되돌린 것으로 취급하지 않는다. 실행기는 명시적으로 허용된 추가 회차 2·3에 한해 기존 정답표 해시, 첫 회차 봉인, 동일 풀이 입력을 확인하고 신규 실행을 허용한다.
- 조정자는 1회차 점수와 오답 정보를 알고 있지만 풀이를 수행하지 않는다. 실제 솔버는 해당 맥락을 상속하지 않는다. 격리는 도구 제한·별도 세션·로그 감사에 의한 논리적 격리다.

## 추가 회차 채점과 보고

- 6개 1차 회차와 3개 진단 회차의 봉인이 모두 존재하고 원본 답안·로그·조건·모델·도구 감사를 통과해야 통합 채점한다.
- 기존 정답가안 JSON과 같은 해시를 사용한다. 확정 정답 대조는 추가하지 않는다.
- 통합 보고서는 각 조건의 1·2·3회 정답 수, 평균, 회차 간 답렬 일치, 모든 오답 및 저신뢰 문항, 진단 결과를 제시한다.
- 최초 키 공개 시각과 후속 회차 통합 채점 시각을 구별한다. 첫 회차의 안내 메시지 감사 수정(수정01)도 계속 공개한다.
- frozen 조건을 갱신하는 파일은 실행기·채점기·환경 메타데이터·이번 수정 문서·CONTINUATION.json뿐이다. 풀이 지침·문제·사용 도구를 바꾸지 않는다.
